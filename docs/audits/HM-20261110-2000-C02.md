## Reproduced code defects and fix

1. The detail page omitted `minIncome` and household bounds, and sliced explicit household maxima to four entries. The fix displays stored minimums, household bounds and all explicit columns, including households 5–7. Rent and unit-specific rows remain intact. Missing project-specific requirements get a visible bilingual warning; general HPD maxima are explicitly labelled reference estimates, not the project's published chart. No missing figures are synthesized.
2. The matcher treated a missing minimum as if no minimum applied, and could combine a household-size pass from one band with an income pass from another band lacking its own household-size rules. A positive published income fit now needs the explicit maximum for this household, minimum, household bounds and unit-size pairing on the same fitting row; otherwise the fitting-but-incomplete row stays unknown. One complete published fit is sufficient even if another row is estimated. Fit facts exclude incomplete/estimated rows.
3. Bedroom preferences formerly used whole-building inventory even when the exact qualifying row named another unit. Exact qualifying unit sizes now drive that preference when available; listing eligibility status remains independent of bedroom preference. Coarse/unpaired data retains the previous inventory fallback and its uncertainty behavior.

A read-only impact sweep across 129,990 synthetic household/listing pairs found 14 status changes (none among primary lotteries) and 140 preference changes for a 2BR preference. This quantifies code behavior on the snapshot; it is not applicant eligibility verification.
