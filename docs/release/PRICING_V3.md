## What this increment changes

- `/chat`: native EN/中文 FAQ/Gemini UI; explicit unchecked provider consent, generic-question warning, bounded inputs, plain-text answers, error/quota/upgrade states. No chat history replay or browser storage. Conversation exists only in the current React page memory. No server-side question/answer logging.
- Replaceable `ChatProvider` (`src/lib/chat/provider.ts`) uses the **existing** Google Apps Script `doPost` contract `{question}` → `{answer,source:'faq'|'gemini'}`. No new Gemini backend, RAG, Premium or Easy Apply. Error-source, HTML/login, oversized/non-2xx responses fail closed. POST is never replayed on redirect; only a Google ContentService 302/303 GET is accepted, without credentials/question body. Total upstream timeout 12 seconds, response cap 64 KiB. Rendered answer is escaped text, never HTML.
- `/pricing`: Free $0 / 1 message/day; Basic $4.99/month / 5; Smart $9.99/month / 15. Email listing alerts have an opt-in **preference only**, clearly marked delivery inactive. Smart guidance is provided through the same FAQ/Gemini adapter; it is not a new validated matching or document-review service. All search, AMI, anonymous Quiz and existing free personalized results remain free.
- Chat requires a **verified free account** even for Free. This makes the daily cap account based, rather than resettable cookies/IPs. Quotas are not a complete anti-Sybil/bot system; approved Auth signup limits/abuse controls remain a gate. One in-flight request per account, atomic DB reservation/finalization, duplicate request IDs rejected, 10 reservations/minute failure-attempt cap, successful answers only consume usage. Provider failures release reservations; abandoned leases expire after 2 minutes (longer than the 12-second provider deadline). Late completion cannot charge/deliver after expiry. No question text/hash is stored. Successful commit followed by network loss is an unavoidable ambiguous delivery case: the committed successful provider result counts, retries never charge the same request again, and we do not retain/replay an answer. UI does not claim network-delivery exactly once.
- Daily bucket and next reset are computed in Postgres using `clock_timestamp()` and **America/New_York**, not supplied by clients. DST days may be 23/25 hours. A request crossing midnight settles its reserved day's bucket; subsequent requests use the new day. Downgrade/expiry never resets today's used count.
- TEST subscription Checkout: verified account + exact configured Origin + strict consent/plan schema. Server-fixed amounts and recurring interval; no client user/amount/entitlement accepted. No live key, Production environment or unknown Checkout destination. Terms version/acceptance recorded server-side. Known-customer binding, unique Checkout attempt and Stripe idempotency. An ambiguous creation stays blocked for operator reconciliation, rather than risking a duplicate purchase. A prior completed active subscription cannot start a second subscription even if its webhook is delayed. Only a verified expired Checkout or canceled/incomplete-expired subscription can clear the previous purchase gate.
- Raw signed TEST webhook → serialized per-account lease → retrieve **current** Stripe subscription + paid invoice; validate monthly USD fixed amount, quantity one, active/not trial/past-due and future period end. Only a locally authorized Checkout/current subscription can update entitlements. Event dedupe and lease token checks are transactional. Out-of-order event bodies never replay old status. Provider/DB errors return non-2xx for Stripe retry. No entitlements granted by a success URL/browser. Plan switching/proration is deferred; the UI disables a second purchase for paid accounts and explains waiting until the current period ends. Cancellation requests stop renewal at period end; verified provider reconciliation and stored expiry control access. Subscription refunds are not exposed; refund/dispute/support policy must be approved before real-money use. Stripe automatic tax/coupons/trials are not enabled.
- `/consultation`: existing **Chinese Google Form**, $59/30min, $99/60min, no Stripe consultation checkout, no new form. EN emphasizes free tools/chat plans; Chinese also has the optional consultation CTA. External link uses no-referrer/noopener; no automatic Form request, response copying or email. Legacy booking/payment routes now return **410** regardless of old enablement flags; old pages redirect to `/consultation`. Earlier SQL/helpers/tests are retained for audit/history, not an active payment path. Previous Phase 1/2 legal-copy pages remain drafts and do not authorize that old flow.
- GTM foundation: default-OFF, opt-in local dataLayer only; no third-party GTM container, analytics ingestion endpoint or paid dashboard installed. Strict event enum, language and optional plan, schema version and document-visit UUID. No full URLs/referrers/query parameters, listing IDs, user/email, income/household attributes, chat text or provider errors. No cross-tab arbitration, sessionStorage session IDs or event replay. Consent choice only is stored locally; withdrawal prevents future events and does not purport to erase anything already delivered. Real registration/activation milestones originate in DB triggers/verified entitlement updates and are claimed once only after consent. Existing historical users are not misattributed as new registrations. Event delivery is best effort/at most once, not a billing/audit ledger; network loss can drop a claimed milestone. Dashboard must distinguish observed milestones from guaranteed conversion counts.
