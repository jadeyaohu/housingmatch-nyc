## Stripe TEST refunds and lifecycle

Existing Checkout, TEST catalog script, signed raw-body webhook, account/subscription lease, event dedupe/current-state reconciliation and end-of-period cancellation are retained. No Products/Prices/charges/refunds were created remotely.

Webhook events now include `charge.refunded`, `refund.created`, `refund.updated`, `refund.failed` in addition to Checkout/subscription/invoice events. Refund events resolve the account's **current** subscription; old/foreign refund data cannot blindly revoke a newer subscription. Every paid grant re-reads the latest invoice's actual InvoicePayments/PaymentIntent/current Charge, rejects live/foreign/unpaid/uncaptured/unsupported payments, and requires no refunded amount. The conservative TEST policy is **any refund on the current paid invoice removes paid entitlement until a verified unrefunded renewal**. Partial refunds also remove access in this TEST implementation; failed refunds are reconciled from current provider state. This is not an approved live-money refund policy. No automatic refund-creation API or optimistic browser grant was added.

Unit acceptance fixtures verify refund revocation, a delayed paid event cannot re-grant the refunded period, provider-read failure releases the lease/retries, partial-refund denial, and a new unrefunded renewal can restore access. Existing activation/failure/cancellation and invalid-signature tests remain. Actual Stripe acceptance is NOT RUN without a connected TEST account.
