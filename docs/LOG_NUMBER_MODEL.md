# Log Number 估算模型（v0 设计稿）

目标：用户输入自己的 Log Number 和基本情况，告诉他"这个号码在这个项目里大概能不能轮到"，并逐条说明依据。
原则：**只用公开规则和公开数据**；输出是区间和档位，不是精确概率；永远不暗示付费能改变结果。

---

## 1. 公开规则（模型的骨架）

| 规则 | 来源 |
|---|---|
| 申请截止后，所有有效申请被**随机排序**并分配 Log Number | Housing Connect FAQ / 项目申请表 FAQ |
| 审核从最小的号码开始，**按顺序往后**找合格的申请人 | 项目申请表 FAQ（"start with the lowest log number and move sequentially"） |
| 优先资格的处理顺序：① 残障（行动不便 5%、视力/听力 2%）→ ② 社区委员会（CB）居民 → ③ 市政府雇员 → 其他优先类别 → 一般申请人 | HPD Marketing Handbook §4-4 |
| CB 优先比例：2024 年 4 月起由 **50% 降到 20%** | HPD Local Law 216 报告 |
| NYC 居民优先；非纽约市居民排在后面（初始租赁期内） | Marketing Handbook |
| 每个项目各户型、各 AMI 档的单位数，以及各优先类别的比例 | NYC Open Data `vy5i-a666`（已在我们数据库里） |

**关键推论：** 一个号码能不能轮到，取决于"排在你前面、并且和你竞争**同一户型 + 同一收入档**、并且最后真的合格并签约的人"有多少，而不是号码本身的大小。

## 2. 公开数据（用来校准）

| 数据 | 数值 | 来源 |
|---|---|---|
| 平均每个项目的申请数 | 约 16,000 | HPD 代理局长在 2025-04-29 市议会听证会上的证词 |
| 2024 年总量 | 约 600 万份申请、1 万多套、300 多个 Lottery | 同上 |
| 不同收入档的竞争差异 | 低收入档每套约 500 份合格申请，高收入档每套约 65 份（2014–2019） | THE CITY 分析 |
| 各阶段人数（申请 → 邀请确认资格 → 选中 → 签约 / 选中但拒绝） | 按收入档、家庭人数、优先类别、区、CD 分列 | HPD Local Law 217 报告（2022-01 至 2024-10 的数据） |

## 3. 估算方法

对用户申请的某一个"户型 × 收入档"：

```
U_gen   = 该档单位数 × (1 − 优先类别占比)          ← 留给一般申请人的单位
e       = 该档的"合格申请比例"（多少申请人真正符合这一档）   ← LL217 校准
y       = 轮到后最终签约的比例（很多人不回复、不合格、放弃） ← LL217 的 签约 ÷ 邀请
N       = 该项目估计的总申请数                         ← 按项目规模和收入档估算

需要往下叫到的号码 ≈ U_gen ÷ (e × y)   （换算成占总申请数的百分位）
用户的位置         = 用户号码 ÷ N       （百分位）
```

如果用户有优先资格（CB、残障、市政府雇员、NYCHA），就在对应的优先池里算一遍，优先池的规模也用 LL217 的数据估算。

**输出不是精确数字，而是三个档位，外加依据：**
- **很可能轮到**：你的位置远在"预计叫到的位置"之前
- **有机会**：在预计范围以内，取决于前面的人放弃了多少
- **可能性低**：远在预计范围之后，建议把精力放在其他项目上

每个结果都要说明用了哪些假设，并提示"数据和每个项目的实际情况可能有很大差异"。

## 4. 绝对不做的事
- 不使用任何非公开数据（项目内部实际叫到的号码、具体申请人数、内部审核标准）
- 不对自己或合作审核人员经手的项目做分析
- 不说、也不暗示"付费能提高被选中的机会"
- 不收集 SSN、证件或任何申请材料

## 5. 需要你来确认的地方（基于你的专业经验，不涉及具体项目）
1. 处理顺序上面写得对不对？现在还有哪些常见的优先类别（退伍军人、NYCHA 居民等），各自比例大概多少？
2. 优先池用完以后，剩下的单位是怎么分配的？非纽约市居民是在什么时候被处理的？
3. "轮到后最终签约的比例"，一般大概在什么范围？（只要一般性的区间，用来检查 LL217 算出来的数字是否合理）
4. 用户拿到号码后最常问的三个问题是什么？这决定了结果页面先展示什么。
